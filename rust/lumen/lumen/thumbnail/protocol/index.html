lumen::thumbnail

Module protocol 

Source
Expand description

URI scheme handlers that serve media and thumbnails to the webview.

The single entry point handle_lumen_request is registered twice in main.rs (as an asynchronous scheme handler) and serves two schemes:

  • lumen:// - full-size media: re-encodes images to JPEG once and caches them; passes videos and already-decodable remote bytes through.
  • lumen-thumb:// - on-demand thumbnails: decodes/requests the source at a requested width w and JPEG quality q, then caches the result.

§URL format

lumen-thumb://?src=<source>&w=<width>&q=<quality>
lumen://?src=<source>
  • src (required) - local absolute path or http(s):// URL.
  • w (optional) - target width in pixels; defaults to 480. Height is derived from the source aspect ratio.
  • q (optional) - JPEG quality 1..=100; defaults to 82 (thumbs) or 88 (full-size Unsplash sources).

Under WebView2 the same URLs are seen as http://lumen.localhost/... or http://lumen-thumb.localhost/..., and both prefixes are accepted here. The frontend builds these URLs with lumenUrl() / lumenThumbUrl() in src/services/lumen-url.ts.

§Behavior

  • Processing runs on a dedicated thread; the responder is invoked exactly once from that thread after the work finishes.
  • Two webview events are emitted around the work for UI feedback: lumen:optimizing (payload: the src string) when processing starts and lumen:optimized when it finishes, regardless of success.
  • Successful responses carry Access-Control-Allow-Origin: * and Cache-Control: public, max-age=31536000, immutable, since cache file names are derived from the source hash and dimensions.
  • Sized variants are cached under <app-data>/lumen/cache/thumbs (local) or .../remote-thumbs (remote) as <blake3(src)>_q<q>_<w>x<h>.jpg. An in-memory index avoids re-scanning the directory, and an existing cache entry whose width is within 1.5x of the request is reused instead of re-encoding.
  • Unsplash sources are rewritten to Unsplash’s image CDN parameters (w, q, fit, fm=jpg, auto=format) so resizing happens upstream.
  • Local images take a fast path: OS Shell thumbnail first, then a scaled JPEG decode that only computes the DCT blocks needed for the target width, then a full image crate decode.

Constants§

DEFAULT_THUMB 🔒
Width used for lumen-thumb:// requests that omit the w parameter.
JPEG_QUALITY_FULL 🔒
JPEG quality for full-size (lumen://) re-encoded images.

JPEG quality for generated thumbnails when q is omitted.
TOLERANCE 🔒
Width multiplier defining when an already-cached thumbnail is “close enough” to reuse: a cached image at most 1.5x the requested width and of the same quality is served instead of re-encoding.
