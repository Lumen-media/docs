Lumen’s module (extension) runtime.

A module is an installable bundle - a .lumenpack (ZIP with a manifest.json) or a source directory - that extends Lumen with extra UI and logic. This module owns the whole lifecycle and the two boundaries a module runs behind:

  • the install boundary: manifest defines the manifest schema and install extracts packs while rejecting path traversal, registry records what is installed, and store resolves, downloads and installs modules from the community catalog;
  • the runtime boundary: enabled modules get a scoped filesystem (module_fs_*), a per-module JSON/SQLite data store, a permission-checked HTTP proxy (net::module_net_request) and a sandboxed asset origin (protocol) served over the lumen-module:// URI scheme.

Shared state lives in ModuleRuntime, stored via Tauri’s managed state, and the cached SQLite handles live in SqliteConnectionCache. Every #[tauri::command] in this module (and its children) is part of the frontend-facing API; each command documents its module_*/store_* name and payload shape.

§Examples

use crate::module_runtime::ModuleRuntime;
// During app setup:
let runtime = ModuleRuntime::init(&app)?;
app.manage(runtime);
app.manage(crate::module_runtime::SqliteConnectionCache::new());

SqliteConnectionCache
Holds cached SQLite connections per module so each exec/query/migrate call reuses the same connection instead of opening a new one every time. Eliminates the overhead of rusqlite::Connection::open() + PRAGMA setup on every Tauri IPC call.
