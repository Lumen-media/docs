Module dev_server 

Source
Expand description

Loopback HTTP server used while developing modules.

start_dev_server runs an [axum] server bound to 127.0.0.1:5179 that exposes the module runtime over plain HTTP so a module’s build tooling (or a browser) can install, reload, disable and uninstall modules and read module files without going through the Tauri IPC bridge.

Endpoints:

methodpathaction
GET/moduleslist all registered modules
POST/modulesinstall ({ path, dev_mode })
POST/modules/{id}/reloademit module:reload
POST/modules/{id}/disabledisable a module
DELETE/modules/{id}uninstall a module
GET/module-files/*pathserve {module_id}/{file}

The server is only ever started on the loopback interface and failure to bind (for example when another instance is running) is logged rather than propagated.

Functions§

disable_module 🔒
POST /modules/{id}/disable: disables a module via super::module_disable. Returns 400 on failure.
install_module 🔒
POST /modules: installs a module from a path, delegating to super::module_install. Returns 400 with the error message on failure.
list_modules 🔒
GET /modules: lists every registered module (enabled or not).
reload_module 🔒
POST /modules/{id}/reload: emits module:reload so the frontend reloads the module. Returns 500 if the event cannot be emitted.
serve_module_file 🔒
GET /module-files/{module_id}/{file}: serves a file from a module’s directory with a minimal MIME mapping and permissive CORS. Returns 400 for a malformed path, 404 when the module or file is missing.
start_dev_server
Starts the development server on 127.0.0.1:DEV_SERVER_PORT.
uninstall_module 🔒
DELETE /modules/{id}: uninstalls a module via super::module_uninstall. Returns 400 on failure.
