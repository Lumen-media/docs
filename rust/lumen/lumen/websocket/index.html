Module websocket 

Source
Expand description

WebSocket server for remote control.

Each accepted TCP connection is upgraded to a WebSocket and split into two paths depending on the peer address:

  • loopback peers are treated as internal connections (the desktop app’s own windows/tools) and may emit raw audio events without pairing;
  • every other peer is external and must first pair with a registration token (register) or authenticate with a stored access token (auth) before any other event is processed.

External events are permission-checked per device, then dispatched to the streaming, chat or audio subsystems. Outbound messages are written through an unbounded channel so the read loop never blocks on a slow client.
