1//! Live streaming subsystem for Lumen events.
2//!
3//! The streaming stack turns the desktop app into a small WebRTC media hub:
4//! it publishes local tracks (desktop preview, app preview, main output,
5//! mobile preview relay and per-device audio) to subscribers, ingests the
6//! camera/microphone feeds sent by mobile devices, and can mirror the current
7//! slide to a plain HTML page for external displays or projectors.
8//!
9//! # Module layout
10//!
11//! * [`config`] - persistent [`config::StreamingConfig`] and the derived
12//!   [`config::StreamingStatus`] snapshot shared with the frontend.
13//! * [`manager`] - [`manager::StreamManager`], the shared state that owns
14//!   tracks, peer connections, volumes and the HTML server runtime, plus the
15//!   Tauri commands used by the desktop webview.
16//! * [`signaling`] - WebSocket-facing helpers: stream type negotiation, SDP
17//!   offer/answer exchange, ICE candidate relay, mobile offer handling and
18//!   the codec capabilities used to build every track.
19//! * [`html_server`] - local HTTP/WebSocket server that renders the current
20//!   slide as a full-screen HTML presentation.
21//! * [`app_preview_producer`] - background producer that captures the app
22//!   window, encodes it with OpenH264 and writes it to the app preview track.
23//!
24//! # Frontend API
25//!
26//! The desktop webview drives this module through the Tauri commands defined
27//! in [`manager`] (`get_streaming_config`, `update_streaming_config`,
28//! `get_streaming_status`, `set_stream_content_protected`,
29//! `set_stream_master_volume`, `set_stream_device_volume`,
30//! `push_stream_slide`, `push_stream_blank` and `set_mobile_preview_device`).
31//! Remote devices negotiate media over WebSocket using the `subscribe_stream`,
32//! `unsubscribe_stream`, `webrtc_answer`, `webrtc_ice_candidate` and
33//! `mobile_offer` events dispatched by `crate::websocket`.
34//!
35//! # Events
36//!
37//! The subsystem emits these Tauri events to the desktop webview:
38//!
39//! * `streaming_status_changed` - status snapshot after any state change.
40//! * `mobile_stream_started`, `mobile_stream_ended`,
41//!   `mobile_stream_orientation_changed` - mobile ingestion lifecycle.
42//! * `mobile_preview_forward_stats` - periodic RTP forwarding counters.
43//! * `streaming_debug_log` - diagnostics from the signaling layer and the
44//!   app preview producer.
